# GitHub Global - 快速启动说明

本文档只负责一件事：帮助你把当前仓库在本地跑起来，并完成第一次登录、仓库同步和翻译配置验证。

如果你想先了解项目做什么、适合什么场景，请先读 [README.md](../README.md)。

## 前置要求

- Node.js 20+
- 一个可访问的 Supabase PostgreSQL 数据库
- 一个已创建的 GitHub App
- 一个可用的 OpenRouter API Key

建议先准备好两份专题文档：

- [GitHub-App配置指南.md](GitHub-App配置指南.md)
- [OpenRouter-API配置指南.md](OpenRouter-API配置指南.md)

## 步骤 1：安装依赖

```bash
npm install
```

## 步骤 2：配置环境变量

复制模板文件：

```bash
copy .env.example .env.local
```

然后编辑 `.env.local`，填入实际的数据库连接串和其他配置。

根目录的 `.env` 仅保留 Prisma CLI 需要的数据库连接，内容与 `.env.local` 中的 `DATABASE_URL` 和 `DIRECT_URL` 保持一致。

`.env.local` 至少需要配置以下字段：

```env
DATABASE_URL="postgres://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:6543/postgres?pgbouncer=true"
DIRECT_URL="postgres://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres"
ENCRYPTION_KEY="your-64-char-hex-key"

GITHUB_APP_ID="your_github_app_id"
GITHUB_APP_CLIENT_ID="Iv1.1234567890abcdef"
GITHUB_APP_CLIENT_SECRET="your_github_app_client_secret"
GITHUB_APP_USER_CALLBACK_URL="http://localhost:3000/api/auth/callback"
GITHUB_APP_SLUG="your_github_app_slug"
GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\n...\n-----END RSA PRIVATE KEY-----"
GITHUB_APP_WEBHOOK_SECRET="your_webhook_secret"

APP_BASE_URL="http://localhost:3000"
GITHUB_APP_WEBHOOK_URL="https://your-public-domain.example.com/api/webhooks/github"
QUEUE_CONCURRENCY=5
```

约定说明：

- `.env.local` 保存完整应用配置。
- `.env` 保留 `DATABASE_URL` 和 `DIRECT_URL`，避免 Prisma CLI 与应用运行时读到两套不同配置。
- 本地开发统一使用 `localhost`，不要混用 `127.0.0.1`。
- `GITHUB_APP_WEBHOOK_URL` 只在你启用自动触发时需要重点配置，而且必须使用公网可访问地址；不是 `localhost`。

## 步骤 3：同步数据库

```bash
npx prisma db push
```

数据库使用 Supabase 托管 PostgreSQL，schema 变更通过 `prisma db push` 同步。

## 步骤 4：启动开发服务

```bash
npm run dev
```

访问：

```text
http://localhost:3000
```

## 步骤 5：完成第一次登录与仓库同步

1. 打开首页 `/`
2. 点击"使用 GitHub 登录"
3. GitHub App 用户授权成功后进入 `/dashboard`
4. 进入 `/repositories`
5. 使用 GitHub App 安装入口授权仓库访问
6. 返回仓库页并刷新列表
7. 打开某个仓库的配置页，填写目标语言和 OpenRouter 模型

当前正常登录流程不再经过 `/login` 页面。

## 步骤 6：验证翻译链路

建议至少完成以下检查：

- `/api/auth/signin` 能正常跳转到 GitHub 授权页
- 回调 `/api/auth/callback` 后能进入 `/dashboard`
- `/repositories` 能看到已授权仓库
- 仓库配置页能拉取候选文件和监听分支
- 保存配置后可以手动触发翻译任务
- `/tasks` 能看到任务状态、失败原因或 PR 链接

补充说明：

- 如果你还没有配置公网 Webhook，这里依然可以验证"手动触发翻译"
- 只有在你要验证 GitHub 事件自动触发时，才需要继续配置 Webhook

## 常见问题

### 1. GitHub 登录回调失败

检查：

- GitHub App 后台配置的 callback URL 是否与 `GITHUB_APP_USER_CALLBACK_URL` 一致
- 当前访问域名是否为 `http://localhost:3000`
- 是否误用了 `127.0.0.1`

### 2. 登录后又被送回 GitHub 登录

先检查：

- 当前服务是否已经重启到最新代码
- 浏览器是否确实使用 `http://localhost:3000`
- Cookie 是否被浏览器拦截

### 3. GitHub App 安装后仓库不显示

检查：

- 安装时是否选择了仓库
- App 权限是否包含仓库内容和 Pull Requests
- 返回 `/repositories` 后是否已刷新仓库列表

### 4. Webhook 本地不可达

GitHub App 的 Webhook 需要公网地址。本地联调可使用隧道工具，例如：

```bash
ngrok http 3000
```

然后把 GitHub App 后台的 Webhook URL 和 `GITHUB_APP_WEBHOOK_URL` 同步改成该公网地址。

如果你暂时只想跑通登录、仓库同步和手动翻译，可以先跳过这一步。

### 5. OpenRouter 模型列表为空

当前 `GET /api/openrouter/models` 依赖外部网络；如果 OpenRouter 不可达，接口会返回空数组和 `500`。请先检查本地网络或代理配置。

### 6. 数据库连接报 "Tenant or user not found"

检查：

- `.env.local` 和 `.env` 中的连接串是否使用 `postgres://` 协议（不是 `mysql://`）
- Supabase 项目是否处于 Active 状态（暂停的需先恢复）
- 密码中如有特殊字符，确认连接串中未发生截断
